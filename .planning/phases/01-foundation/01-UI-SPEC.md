# Phase 1 — UI Design Contract

> Visual and interaction contract for Phase 1 (Foundation). Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (manual Tailwind CSS) |
| Preset | not applicable |
| Component library | none (Phase 1 uses custom components only) |
| Icon library | Lucide (install but minimal use in Phase 1) |
| Font | Inter, system-ui, -apple-system, sans-serif |

**Rationale:** Phase 1 is a foundation phase — Electron shell, IPC, dark theme, lazy-loading infrastructure. The UI surface is minimal (window shell + welcome screen + skeleton components). shadcn is deferred to Phase 2 when tabbed artifact viewing, file browser, and split-pane layouts need accessible primitives. Tailwind CSS 4 `@theme` directive handles the palette directly. Lucide is installed now to establish the icon dependency tree early.

| Text primary | `#bebebe` | Body text, primary labels |
| Text secondary | `#8a8a8a` | Secondary labels, metadata, placeholder text |
| Text faint | `#7aa2f7` | Less prominent text, code comments reference |
| Text accent | `#0fb6d6` | Accent-colored text (links, active labels) |
| Destructive | `#f95959` | Destructive actions only (close buttons, delete) |
| Success | `#17b978` | Success indicators, connection status |
| Warning | `#ffc93c` | Warning indicators |
| Border default | `rgba(14, 210, 247, 0.15)` | Default dividers, card borders |
| Border accent | `rgba(14, 210, 247, 0.3)` | Focus rings, active tab borders |

Accent reserved for:
- Interactive elements: buttons, links, clickable icons
- Active/selection states: selected tab indicator, focused input ring, active nav item
- Chrome borders: window chrome-style borders for panels
- Code keyword highlighting in future viewers
- Logo/brand accent elements in welcome screen
- NOT: background fills, large surface areas, passive decoration, body text

## Component Inventory

Components that Phase 1 must produce:

| Component | File (proposed) | Description |
|-----------|----------------|-------------|
| `App.tsx` | `src/renderer/App.tsx` | Root component — renders WelcomeScreen |

## Interaction States

Phase 1 interactions are minimal. Define the contracts for what exists:

### Welcome Screen
| State | Visual | Behavior |
|-------|--------|----------|
| Default | Centered app name (Display 28px, weight 600), tagline (Body 16px, weight 400, text-secondary), version string (Label 14px, text-faint) | Static display. No user interaction. |
| IPC ready | (Same as default) | The version string is populated via `electronAPI.app.getVersion()` — this confirms IPC is working. If IPC fails, version shows a dash or error state. |
| IPC error | Version area shows `—` or error state | Handled via `useElectronAPI` hook error state. |

### Skeleton Screens
| State | Visual | Behavior |
|-------|--------|----------|
| Loading | Shimmer animation: gradient sweep across secondary/elevated background colors | CSS `@keyframes shimmer`, 1.5s infinite, `background-size: 200% 100%` |
| Content loaded | (Viewer content — Phase 2+) | Skeleton replaced by lazy-loaded component |
| Error | (Phase 2+ — error boundary component) | Skeleton replaced by error fallback |

### IPC Bridge
| State | Visual | Behavior |
|-------|--------|----------|
| Connected | Version loads successfully | `electronAPI.app.getVersion()` returns string |
| Disconnected | Version shows `—` or error display | `useEffect` catches error, sets fallback state |
| Invocation | No visual indicator (IPC is transparent) | `ipcRenderer.invoke()` calls are async — no loading state needed for app:getVersion since it's near-instantaneous |
